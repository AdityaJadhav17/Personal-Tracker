# US-100 Sync Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `serve.mjs` keeps one shared copy of the database on the laptop's disk and lets only Margin itself read and replace it, with a revision number so two devices cannot overwrite each other. Nothing calls it yet.

**Architecture:** A new `scripts/hub.mjs` (Node built-ins only) reads and writes `hub.json` crash-safely with a revision. `serve.mjs` routes `GET` and `PUT /api/sync` to it after an authorisation check that needs a custom header, and under the tailnet name, Tailscale's identity header for the laptop's own login. The server does not merge; US-101's app does.

**Tech Stack:** Node 22 built-ins (`node:fs`, `node:http`, `node:path`), Vitest for `scripts/*.test.mjs`.

**Spec:** `docs/engineering/sync-design.md`, section 2.

## Global Constraints

- `scripts/serve.mjs` uses Node's own modules only (the updater reinstalls `node_modules` under it).
- Never run the server on 4180 in tests: a scratch `PT_TARGET`, `PT_PORT` and `PT_DATA`.
- Test-first; AC IDs in test names; Aditya runs git.
- The body is capped at 5 MB, the same cap as import.
- Full checks before handing over.

```markdown
# US-100, a shared copy on the laptop that only Margin can reach

US-100 As someone about to sync two devices,
I want the laptop to keep one shared copy that only Margin can read or replace,
so that each device has somewhere private to meet.

Acceptance criteria:
AC-100.1 GET /api/sync answers { revision, db }: revision 0 and db null
before anything is stored.
AC-100.2 PUT /api/sync with { revision, db } stores db only if revision is
the current one, answering the next revision; otherwise 409 and
nothing changes.
AC-100.3 Every request needs the header X-Margin-Sync: 1, and a PUT a JSON
body; without them, 403. A web page on another site cannot send
either.
AC-100.4 Under the laptop's Tailscale name, Tailscale-User-Login must be
the laptop's own login; otherwise 403.
AC-100.5 A body over 5 MB, or one whose db is not a database, is refused
with 400. The copy is written to a new file and renamed over the
old, which is kept as hub.prev.json.
```

```js
/**
 * US-100. The one shared copy of the database that the laptop and the phone
 * meet at, with a revision so two writers cannot overwrite each other.
 * Written to a new file and renamed over the old, so a crash mid-write
 * leaves the last good copy; the one before is kept too.
 */
import {
  copyFileSync,
  existsSync,
  mkdirSync,
  readFileSync,
  renameSync,
  writeFileSync,
} from 'node:fs';
import { join } from 'node:path';

const HUB = 'hub.json';

export function readHub(dir) {
  // A damaged copy falls back to the one before it, rather than failing the
  // request in the process that serves the app (council, 13 October).
  for (const name of [HUB, 'hub.prev.json']) {
    const file = join(dir, name);
    if (!existsSync(file)) continue;
    try {
      return JSON.parse(readFileSync(file, 'utf8'));
    } catch {
      // try the previous copy
    }
  }
  return { revision: 0, db: null };
}

export function writeHub(dir, revision, db) {
  if (readHub(dir).revision !== revision) return { ok: false };
  mkdirSync(dir, { recursive: true });
  const file = join(dir, HUB);
  const next = { revision: revision + 1, db };
  writeFileSync(`${file}.tmp`, JSON.stringify(next));
  if (existsSync(file)) copyFileSync(file, join(dir, 'hub.prev.json'));
  renameSync(`${file}.tmp`, file);
  return { ok: true, revision: next.revision };
}
```

(Node handles one request at a time on its event loop and these calls are synchronous, so read-check-write cannot interleave between two requests.)

```js
/** AC-100.4. The login that owns this laptop on the tailnet. */
export function tailnetLoginFrom(status) {
  try {
    const parsed = JSON.parse(status);
    const login = parsed?.User?.[parsed?.Self?.UserID]?.LoginName;
    return typeof login === 'string' && login !== '' ? login : null;
  } catch {
    return null;
  }
}

/**
 * AC-100.3 and AC-100.4. A page on another site cannot send a custom header
 * or a JSON body without asking first, and this server never answers the
 * asking; through Tailscale, the caller must also be this laptop's owner,
 * as Tailscale itself vouches.
 */
export function syncAllowed(headers, method, isTailnet, login) {
  if (headers['x-margin-sync'] !== '1') return false;
  if (
    method === 'PUT' &&
    !String(headers['content-type'] ?? '').startsWith('application/json')
  ) {
    return false;
  }
  if (isTailnet)
    return login !== null && headers['tailscale-user-login'] === login;
  return true;
}
```
