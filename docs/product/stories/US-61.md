# US-61, reflections and trends

The last story from the UI audit of 24 September 2026. Built the same day.

```
US-61  As someone looking back over how the term is going,
       I want dates I can read and charts that say what they show,
       so that the history reads without the table beside it.

Priority: Should, built
Acceptance criteria:
  AC-61.1  Past reflections and the Trends table name each day as
           "Wed, Sep 23", never "2026-09-23".
  AC-61.2  The five answers to "How did today go?" read as one segmented
           control: joined, one row, rounded only at the ends. Each is still a
           toggle that says whether it is the day's answer.
  AC-61.3  Each chart prints its scale's two ends and its first and last
           days, and hovering reads out the day under the pointer with its
           value, "Sun, Sep 20 · Good, 4".
```

## Decisions

**The table stays the accessible route.** The readout follows the mouse and
is hidden from assistive tech; the table below carries every number for a
keyboard and a screen reader, as AC-18.4 already required. Before this story
the table was the only route, which the chart's comment defended as the
reason for no hover at all; the comment now says the readout is added on
top, not instead.

**Mood starts at 1.** There is no zero on a one-to-five scale, so the chart's
floor is 1 and the line uses its full height. Items finished starts at 0.

**Labels in HTML beside the SVG.** The plot stretches to its width, which
would squash text drawn inside it, so the scale, dates, guide, marker and
readout are HTML positioned by percentage over the SVG.

**Two charts, still.** The dataviz rule of one axis per chart holds, as it
did since US-18.

## What it took

`shortDay` and `monthDay` in `dates.ts`. Dates of different widths made the
past-days columns wobble, so the date column got a minimum width.
