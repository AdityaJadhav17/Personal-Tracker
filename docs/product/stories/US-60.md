# US-60, courses and goals, list first

The fourth story from the UI audit of 24 September 2026. Built the same day.

```
US-60  As someone who reads Courses and Goals far more than they add to them,
       I want the list first and each course in one colour everywhere,
       so that the page shows what I have, and a class looks the same on
       every view.

Priority: Should, built
Acceptance criteria:
  AC-60.1  With courses or goals already there, the list comes first and the
           form waits behind New course or New goal; adding closes it again,
           and Cancel puts it away. With none yet, the form is open.
  AC-60.2  A card shows no Delete until its More control is opened. Deleting
           still asks first.
  AC-60.3  A course card carries its colour, the one Home uses, by the order
           courses were added. The cards lose the teal stripe.
  AC-60.4  On the calendar, an item's bar takes its course's colour; one with
           no course keeps the accent. High priority reads bold there, as on
           Home.
```

## Decisions

**Open when empty.** With nothing to list, a button in front of the form is
one more click for nothing, so the form shows until the first one exists.

**More, not an edit mode.** Cards have nothing to edit yet, only Delete, so a
whole edit mode would be a costume for one button. `MoreButton` is the three
dots, shared by both card types.

**The calendar's red bar went.** It meant high priority, and the bar now
means the course, which is the question you ask of a calendar: whose is this.
High priority moved to bold, the same signal Home gives it.

## What it took

Tests that add a second course or goal open the form first, and tests that
delete open More first. The More glyph was set at 1.125rem and US-49's check
that large text is tracked tighter caught it; a glyph does not need that
size, so it is 1rem.
