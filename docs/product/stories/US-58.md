# US-58, one place for data

The second story from the UI audit of 24 September 2026, the shared chrome.
Built the same day.

```
US-58  As someone who opens every view many times a day,
       I want the export and import tools in one place, and every view named,
       so that no view ends in a row of buttons it has nothing to do with.

Priority: Should, built
Acceptance criteria:
  AC-58.1  Export, Export calendar, Import, Add from calendar file and Paste
           a list live in a Data view, each with a line saying what it is
           for, and nowhere else. The two file pickers look like the buttons
           beside them, and show a focus ring when reached from the keyboard.
  AC-58.2  When a backup is due, Data in the sidebar carries a dot and the
           description "Backup due", from any view; the Data view says how
           long it has been. Exporting clears both.
  AC-58.3  Every view opens with one level-one heading naming it: Home its
           date, Calendar its month, the others their own name.
```

## Decisions

**A view, not a menu.** Aditya's pick of two. A menu at the sidebar's foot
would have left Paste a list, the calendar-file preview and Replace or Merge
to open in whatever view you were on. A view keeps each tool beside its
result, and file pickers behave like file pickers.

**The reminder follows you.** US-40 put the backup line beside Export so it
sat next to its fix. With Export off Home, the line alone would go unseen, so
Data in the sidebar gets a dot. The button's name stays "Data"; the reminder
is its accessible description, so nothing that looks for the button breaks.

**File pickers dressed as buttons.** The input is visually hidden inside its
label, so the label is what you see and click, the input is still what the
label names, and a test can still hand it a file.

**Titles in one size.** `.page-title` is the size Home's date already uses.
The calendar's month and Trends' heading moved up to it; the rules they had
went.

## What it took

About forty tests used a tool that moved. Unit and end-to-end tests gained
`openData` and `openHome`, and the few that read the list after an import go
back to Home to do it. The accessibility scan and the narrow-screen check now
cover Data. Storage errors still show on every view, since saving happens
everywhere.
