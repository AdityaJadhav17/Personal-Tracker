# US-44, deciding what to do with what is late

Step 6 of [the roadmap](../review-and-roadmap.md). Built 24 September 2026.
Research problem 2: a wall of overdue items turns every morning into guilt
management, and people stop opening the app.

```
US-44  As someone who will sometimes miss things,
       I want each overdue item to ask me for one decision,
       so that the Overdue group empties instead of piling up.

Priority: Should, built
Acceptance criteria:
  AC-44.1  Given an overdue item, its row offers Tomorrow and Drop beside
           Done; an item that is not overdue does not. The Overdue heading
           says what the choices are.
  AC-44.2  Given I press Tomorrow, the deadline moves to tomorrow at the
           time it had, and the item leaves Overdue.
  AC-44.3  Given I press Drop, the app asks; Yes deletes it, Keep does not.
```

## Decisions

**Four choices, two of them new.** Done was already on every row, and "pick a
new date" is opening the row, which is already one click. Only Tomorrow and
Drop are added, and only on overdue rows, so the rest of the list gains
nothing.

**Tomorrow keeps the time.** A 5pm item missed on Tuesday becomes 5pm on
tomorrow's date, through the same `moveToDay` the calendar drag uses.

**Drop deletes, and asks first.** Dropping is deciding not to do it, which is
not the same as doing it, so it must not count as done. Deletion has no undo,
so it asks the way Delete does.
