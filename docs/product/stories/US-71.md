# US-71, leaving the list looks like one thing

From the final UI polish plan, 25 September 2026
([ui-final-polish-plan.md](../../design/ui-final-polish-plan.md)).

```
US-71  As someone clearing out a list,
       I want a deleted or dropped row to leave the way a finished one does,
       and the undo message to wait while I reach for it,
       so that the three ways out look like one and Undo is never snatched.

Priority: Could
Acceptance criteria:
  AC-71.1  Delete and Drop fold the row away, as finishing does, then remove
           it. With reduced motion it goes at once.
  AC-71.2  A tick during the fold is not lost: the delete that follows it
           starts from the database as it is by then.
  AC-71.3  The undo message does not fade while the pointer is on it or it
           has focus.
```

## Decisions

**Delete waits for the fold; done does not.** US-67 saves a tick at once,
because a tick lost to a reload is a lie. A delete lost to a reload leaves
the item where it was, which costs nothing, so it can wait 220ms.
