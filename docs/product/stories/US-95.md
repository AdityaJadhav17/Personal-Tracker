# US-95, automatic backups to a folder on this laptop

Asked for on 12 October 2026, after the council found that the only copy of
everything is one browser's storage, and the only backup is an export
Aditya has to remember. He wants backups kept off the internet: a folder on
C: that OneDrive does not sync, and a flash drive.

```
US-95  As the only person whose data this app holds,
       I want it copied to a folder of my choosing without my doing anything,
       so that clearing the browser, a bad deploy or a broken migration
       costs me at most a day.

Priority: Must
Acceptance criteria:
  AC-95.1  Data offers "Choose backup folder". The folder is picked once,
           and its name is shown afterwards. The page advises a folder
           outside OneDrive, since Documents and Desktop are inside it.
  AC-95.2  With a folder chosen, the app writes the whole database there as
           personal-tracker-backup-YYYY-MM-DD.json: when it opens, and a few
           seconds after any change. One file per day, rewritten through the
           day, in the same format Export makes, so Import restores it.
  AC-95.3  Only the newest 30 daily files are kept; older backup files the
           app made are deleted. Nothing else in the folder is touched.
  AC-95.4  Each automatic backup counts as a backup, so the "Not backed up"
           reminder stays quiet while they are working.
  AC-95.5  When the browser stops allowing the write (a new session, or the
           folder gone, such as an unplugged flash drive), Data says backups
           are paused and why, with one button to allow them again. Nothing
           else in the app is blocked.
  AC-95.6  A browser that cannot write to folders (Safari, the iPhone) does
           not show the option at all.
  AC-95.7  Before a deploy's migration changes the stored version, the app
           keeps the stored text as it was under a second key,
           personal-tracker/before-upgrade, so a bad migration can be undone.
           One copy, the latest: older ones would fill the storage quota.
```

## Decisions

**The File System Access API, not the server.** The page writes into a folder
the user picked, with no server, no network and no dependency. Posting data to
serve.mjs would break "no network request after load".

**IndexedDB holds one thing: the folder.** A folder handle cannot be stored as
text, so it cannot go in localStorage. It goes in IndexedDB, under its own
database, `personal-tracker-backup`. The data itself stays in localStorage.
This narrows the 15 September decision against IndexedDB; it does not reverse
it.

**One file per day.** A file per change would be thousands of files a term. A
day is the most anyone loses.

**The flash drive is a second copy, made by hand.** Copying the backup folder
to the flash drive once a week covers a lost or dead laptop. Pointing the app
at the flash drive works too, but backups pause whenever it is unplugged.
