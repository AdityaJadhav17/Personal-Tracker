# US-87, community files

Asked for on 1 October 2026, from GitHub's community standards checklist.

```
US-87  As the owner of a public repository,
       I want the files GitHub's checklist expects,
       so that anyone who finds it knows how to report a problem safely and
       what a change has to meet.

Priority: Could
Acceptance criteria:
  AC-87.1  CODE_OF_CONDUCT.md, SECURITY.md, two issue forms (bug and story)
           and a pull request template exist, and the checklist shows them.
  AC-87.2  Every form and the security policy warn against posting real
           personal data, and security reports go to a private advisory.
  AC-87.3  ACCESSIBILITY.md says what is checked, on what, what is not yet,
           and how to report a barrier. It claims only what a test checks.
```

## Decisions

**Issue forms ask for a story.** The repo works in user stories with
acceptance criteria, so a feature request is written as one. Blank issues are
off, and the security link points to a private advisory.

**The PR template is the definition of done**, cut to what a reviewer can
check, plus "no real data in the diff".

**A short code of conduct of our own**, in the spirit of the Contributor
Covenant 2.1 and linked to it, rather than its full text: one maintainer, a
small project.

**The description is a GitHub setting**, not a file. Aditya sets it.

**Proof is GitHub's checklist.** No test can see it; after the push, the
community standards page shows each item ticked.
