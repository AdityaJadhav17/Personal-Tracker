# US-52, repeats you can see coming

Reported 24 September 2026: Aditya set rent to repeat monthly and could not
find it in November. Built the same day.

```
US-52  As someone whose rent is due every month,
       I want the calendar to show the months after this one,
       so that looking ahead shows what I already know is coming.

Priority: Must, built
Acceptance criteria:
  AC-52.1  Given an open item repeating monthly, when I look at a later month,
           it shows on the day it would fall due, at the same time, before
           this month's one is finished.
  AC-52.2  Given an open item repeating weekly, a later month shows it every
           week.
  AC-52.3  Given the real item, it shows once and never beside a copy of
           itself; a done or one-off item shows no repeats.
  AC-52.4  A repeat lands where finishing the one before would put it: a
           series aimed at the 31st clamps in February and returns in March,
           and nothing shows before the real item.
  AC-52.5  A week's load counts the repeats that land in it.
  AC-52.6  A repeat is marked as one, to eyes and to screen readers, and
           cannot be dragged.
  AC-52.7  Opening its day says it joins the list when the one before it is
           finished.
```

## Decisions

**Not a bug in the code, a gap in US-28.** That story creates the next round
only when you finish the last, so Home never fills with twelve rent rows. The
calendar is for looking ahead, and there the same rule hid something you know
is coming.

**Worked out for display, never stored.** Option A of three. B, showing them on
Home as well, brings back the clutter US-28 kept out. C, a year of real items
up front, is what US-28 rejected: moving out would mean deleting eleven rows.
The preview uses the same `nextOccurrence` call `markDone` makes, so it lands
where the real one will.

**Counted in the week's load.** Rent is due that week whether or not last
month's is ticked off.

**Not draggable.** Moving a preview would move nothing. Move the real one and
its repeats follow, because they are worked out from it.

**A dashed bar and muted text,** so a repeat reads as expected rather than due,
and stays distinct from a goal's dashed outline.

## Not done

The phone has the same gap. The `.ics` export carries only the open item. A
repeat rule on the exported event would show the series, but once October is
finished November's item has its own id, so the phone would show November
twice. That needs its own story.
