# US-41, a calendar you can open

Step 2 of [the roadmap](../review-and-roadmap.md). Built 24 September 2026,
from the first two days of real use: goals were missing, "2 more" led
nowhere, and an item on the calendar could be dragged but not opened.

```
US-41  As someone planning from the calendar,
       I want to see my goals on it and open any day,
       so that the month view is somewhere I can act, not just look.

Priority: Must, built
Acceptance criteria:
  AC-41.1  Given a goal with a target date,
           then the calendar shows "Goal: name" on that day, outlined rather
           than filled, so it never reads as one more deadline.
  AC-41.2  Given a day with more items than fit,
           when I press "N more",
           then the day opens below the grid listing all of them.
  AC-41.3  Given an item on the calendar,
           when I press it,
           then its day opens, and its row there can change its date without
           a mouse drag.
  AC-41.4  Given any day, even an empty one,
           when I press its date,
           then it opens, and Close shuts it.
```

## Decisions

**One panel, three ways in.** The date, an item and "N more" all open the
same day below the grid. One mechanism, not three.

**The open day uses the dashboard's own row.** `CalendarView` takes a
`renderDay` function, and App hands it the same `ItemRow` the dashboard uses.
Done, note, course, goal, rename, date and delete all work from the calendar
without the calendar knowing any of them exist. The date field there is also
step 3's keyboard way to move an item.

**The open day survives turning the month**, so looking ahead does not lose
what you were reading.

## What it took

Making the date a button with an `aria-label` took the name away from every
calendar cell: the test library's name for a table cell does not follow a
child button's label. The button's name now comes from its own hidden text,
"Open September 16, 2026", which names the button and the cell at once.
