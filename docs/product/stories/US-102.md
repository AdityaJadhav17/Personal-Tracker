# US-102, tighter edges

US-102 As the only user of Margin,
I want every copy of my data, every import and every server answer to keep the same rules,
so that a locked note stays locked and a bad file or request changes nothing.

Acceptance criteria:
AC-102.1 Dates outside the years 1970 to 9999 are refused, in an imported
file and in a synced copy.
AC-102.2 A lock or locked text that is not well-formed is refused on import,
and a lock that cannot be read fails to open cleanly.
AC-102.3 After any save that changes the passcode or locks a note, wherever
it came from, no older copy the app keeps holds that note readable: the
copy kept from before the last upgrade is removed, Undo cannot bring back a
note under an old passcode, and older backups hold only the locked version.
AC-102.4 Sync pauses, and says why, whenever the two devices hold locked
notes under different passcodes, including a passcode set during a sync and
a note locked on one device but readable on the other.
AC-102.5 A note is saved locked only with the current passcode.
AC-102.6 The server serves only regular files inside the app's folder.
AC-102.7 The shared copy refuses a version newer than the app, and keeps no
previous copy that holds a note readable after it was locked.
AC-102.8 The updater remembers what it deployed even when a build fails,
and acts only on a full commit id.
AC-102.9 Dependencies are watched for every package manager the repo uses,
and CI keeps no credential on disk.
