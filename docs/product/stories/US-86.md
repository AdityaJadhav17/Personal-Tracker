# US-86, change the passcode

Asked for on 1 October 2026. US-82 left it out.

```
US-86  As someone who keeps private notes behind one passcode,
       I want to change that passcode,
       so that one I have shared, or think someone saw, stops working.

Priority: Should
Acceptance criteria:
  AC-86.1  With a lock set, Notes offers Change passcode. It asks for the
           current passcode, then a new one twice: at least 6 characters.
  AC-86.2  A wrong current passcode says so and changes nothing.
  AC-86.3  On success every locked note is encrypted again under the new
           passcode, in one write: the old passcode opens nothing, the new one
           opens all of them, and their text and edit times are unchanged.
  AC-86.4  If any locked note will not open with the current passcode, or
           one changes while the change runs, nothing is changed and the app
           says so.
  AC-86.5  Before changing, the app says that backups taken earlier still
           open with the old passcode.
```

## Decisions

**One write, all or nothing.** Every note is re-sealed in memory first, then
the new lock and every note go to storage in a single commit. A note sealed
under the old key beside one under the new would be one neither passcode
fully opens.

**Checked against what is stored at the moment of writing.** Re-sealing is
asynchronous. If a note's stored IV is not the one that was read, it changed
in between, and the whole change is refused rather than overwriting it.

**A note that will not open stops it.** That only happens to a note merged in
from a file locked under another passcode (the US-82 limitation). Changing
around it would leave it under a lock nobody has.

**Old backups keep the old passcode.** An export is a copy of the moment; it
is not rewritten. Said before the change, in words.

**Not an edit.** Edit times stay as they were, as locking and pinning do.

**Not in this story.** A passcode hint, and Windows Hello.
