# US-29, changing your mind about repeating

Found and built 18 September 2026, straight after US-28 shipped. US-25 exists because an
item you cannot correct stops being trusted, and it added a title, a date and a
time to the panel behind the row. US-28 then added a field that panel does not
offer.

## What is missing

`repeat` can be set when an item is created and never again.

- Add rent and forget to set Monthly, and the only way to fix it is to delete
  the item and type it again.
- Move out, and there is no way to stop rent coming back at all. Deleting the
  open one works until you finish the one before it, which makes another.

The second is the one that matters. A feature that creates work on a schedule
needs an off switch, and right now the off switch is deletion.

```
US-29  As someone whose circumstances change,
       I want to change whether an item repeats after I have made it,
       so that a standing commitment can be started and stopped like any
       other field.

Priority: Must, built
Acceptance criteria:
  AC-29.1  Given an open item,
           when I open it,
           then the repeat control shows what that item currently does.
  AC-29.2  Given an item that does not repeat,
           when I set it to monthly and save,
           then the row says Monthly and still does after a reload.
  AC-29.3  Given an item set to repeat,
           when I set it to never and save,
           then the row stops saying it repeats.
  AC-29.4  Given an item I have just stopped repeating,
           when I mark it done,
           then nothing new is created.
  AC-29.5  Given an item set to weekly,
           when I change it to monthly and finish it,
           then the next one is a month later, not a week.
  AC-29.6  Given I change the repeat and nothing else,
           when I save,
           then the title, date and time are untouched.
```

## Decisions

**The same control, in the panel US-22 opens.** Not a new place and not a new
interaction: the repeat is a field of the item like the title is, so it belongs
where the other fields are.

**Save covers all of it, as it already does.** `onEdit` carries the repeat
alongside the title and the date rather than reporting separately, because they
are edited together and saved together.

**Changing the repeat does not touch the schedule.** Setting monthly on an item
due Friday does not move it; it means the one after this is a month on. Making
the edit reschedule the item as well would be two things happening for one
action.

## What it took

One select in the panel, and `repeat` carried on `onEdit` alongside the title
and the date. The hook's `editItem` already mapped over the item, so it gained
one field.

**A sixth locator collision, and the first one that is a design signal.** The
badge on a row reads "Monthly" and so does an option in the repeat select that
now sits in the same row when it is open, so a scoped query matched twice inside
one list item. The fix is that the test closes the row after saving, which is
what a person does anyway. The words are right for both places, so this one
stays as it is rather than being renamed to suit a query.
