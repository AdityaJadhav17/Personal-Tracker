# US-46, alarms that mean something

Step 4 of [the roadmap](../review-and-roadmap.md). Built 24 September 2026.
Research problem 5: when everything is an alarm, nothing is.

The export gave every deadline the same alarm, 90 minutes before it was due,
from "book PrairieTest" to the CSE 120 final. Eighteen syllabus deadlines is
eighteen identical interruptions, and people learn to dismiss those unread.

```
US-46  As someone who gets too many notifications already,
       I want my phone's alarms to scale with how much a deadline matters,
       so that the ones that fire are the ones I act on.

Priority: Should, built
Acceptance criteria:
  AC-46.1  Given a high priority item, the exported event warns a day before
           and an hour before the deadline.
  AC-46.2  Given a normal item, it warns once, at 8pm the evening before,
           including across the November clock change.
  AC-46.3  Given a low priority item, the event carries no alarm at all.
```

## Decisions

**Priority already exists, so it decides.** No new setting. Exams went in as
high priority, which is exactly the tier that should shout.

**8pm the evening before** is a time you can still do something about it,
unlike an alarm at 11:29pm for an 11:59pm submission.

**Every trigger is minutes before the event's start.** That is the default a
trigger is measured from and the form every calendar app reads. `RELATED=END`
or absolute times would have been shorter to write and riskier on a phone.

**The evening is built from the local date**, not by subtracting hours, so
the Sunday the clocks go back still alarms at 8pm, not 7pm.
