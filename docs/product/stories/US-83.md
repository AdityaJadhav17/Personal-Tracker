# US-83, the security audit of 30 September

The whole-repo audit of 30 September 2026 found nothing high or medium, and
six low items. Aditya asked for all six to be fixed.

```
US-83  As the only person whose data this app holds,
       I want the six gaps the audit found closed,
       so that the protections the app claims are the ones it has, and the
       tests would notice if one went missing.

Priority: Should
Acceptance criteria:
  AC-83.1  The off-origin spec compares origins, not string prefixes, watches
           WebSockets too, goes through import, notes and the calendar before
           checking, and checks the CSP is on the page.
  AC-83.2  The passcode fields ask the browser not to save the passcode.
  AC-83.3  An imported locked note keeps only its IV and its data; anything
           else inside it is dropped.
  AC-83.4  The server on 4180 answers only requests addressed to localhost or
           127.0.0.1 on its own port; any other Host gets a 403.
  AC-83.5  The updater deploys only once the CI run itself, the check named
           check, has passed; other checks passing is not enough.
  AC-83.6  npm audit reports nothing: Vitest moves from 3.2 to 4.1.11, which
           fixes GHSA-82fw-gwwq-j7x9 and still runs on Node 20.
```

## Decisions

**Vitest 4, not 5.** 5.0 also fixes it but needs Node 22.12, and CI runs on
Node 20. 4.1.11 is the patched release on the line that still supports it.

**autocomplete="off" is a request.** Browsers may still offer to save a
password field. It is the strongest thing a page can ask for.

**A wrong Host is refused, not redirected.** Nothing legitimate reaches the
server by another name.
