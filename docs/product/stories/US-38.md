# US-38, opening it without a terminal

Asked for and built 23 September 2026. Using the app meant opening this repo and
running `npm run dev` every time, which is too much friction for something whose
value is being quick to check.

```
US-38  As someone who adds things between other things,
       I want to open the tracker from an icon without starting anything,
       so that checking it costs a click rather than a terminal.

Priority: Must, built
Acceptance criteria:
  AC-38.1  Given the repo,
           when I run npm run deploy,
           then the build lands outside the repo and dist is not the copy I use.
  AC-38.2  Given a deployed copy,
           when npm run live is running,
           then the app is at localhost:4180 and listens on this laptop only.
  AC-38.3  Given the live server is running,
           when I deploy again,
           then a reload shows the new build without restarting anything.
  AC-38.4  Given I add an item at 4180,
           when I reload,
           then it is still there, and nothing off-origin was requested.
```

## Decisions

**No Docker.** The app is static files with no backend. On Windows 11 Home,
Docker means Docker Desktop and WSL2 starting at login to serve 186 KB. It earns
its place when there is a real server process, which is v3 phase one.

**A separate copy outside the repo.** Serving the repo's `dist/` would mean the
everyday app ran whatever branch was last built, including half-finished work.

**A separate port, 4180.** Storage is per origin, so this also separates real
data from development. Playwright reuses whatever answers on 5173, so the live
server must never sit there. And real data at 5173 is how an item was wiped
twice during development in this project.

**A visible, minimized window at login rather than a hidden service.** You can
see it is running and close it to stop it. Nothing about it is secret.

## What it took

The acceptance criteria describe machine setup rather than app behaviour, so
they have no Vitest or Playwright test in the suite. That breaks the
test-per-criterion rule, and deliberately: a test would have to build into
the user's profile and hold port 4180 on every CI run. Each was checked by
hand instead. The build landed in `%LOCALAPPDATA%\PersonalTracker`. The server
listened on `[::1]:4180` only. A file added after start was served without a
restart, and a redeploy while running succeeded. A Playwright script added an
item, reloaded, found it, and saw zero off-origin requests.

The Startup shortcut is not created by the repo. The agent's sandbox refused
to write it, correctly, as persistence, and the README gives the one command to
run.
