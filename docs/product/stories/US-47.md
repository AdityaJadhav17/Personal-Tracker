# US-47, motion that feels right

Phase 1 of the [UI polish plan](../../design/ui-polish-plan.md), from
review-animations and emil-design-eng. Built 24 September 2026.

```
US-47  As someone who clicks through this app many times a day,
       I want presses to feel answered and nothing to move that should not,
       so that the app feels responsive without feeling busy.

Priority: Should, built
Acceptance criteria:
  AC-47.1  Given a button, pressing it dips it to 97% over 160ms with a strong
           ease-out, and it springs back on release.
  AC-47.2  Given reduced motion is asked for, a press does not move, but
           colour changes still ease over their usual 150ms.
  AC-47.3  Given a touch screen, no hover style can stick after a tap: every
           :hover rule is gated to a precise pointer.
  AC-47.4  Given any element, nothing transitions for longer than 300ms, and
           nothing uses ease-in.
```

## Decisions

**Tokens, not values.** `--ease-out`, `--press-scale` and `--rise` live in
`styles/base.css`. Reduced motion sets the two distances to nothing in
`styles/motion.css`, which stills every press and entrance in one place and
leaves colour changes alone: "reduce, don't eliminate". The old rule cut every
duration to 0.01ms, colour included.

**`scale`, not `transform`.** The press uses the individual `scale` property,
so it cannot fight a `transform` a component already has.

**Which buttons.** Add, the data row, prompts, month moves, filters, reflection
scores, the sidebar and Done. Not calendar items, where a press starts a drag
and a shrinking source looks wrong, and not the text-link buttons (item titles,
calendar dates, "more"), which read as links.

**Hover keeps `ease`.** STANDARDS.md: hover and colour change use `ease`; the
strong ease-out is for presses, entrances and exits. The two transitions that
named no curve now say `ease`.

## What it took

A first hover test tapped a button in touch emulation and checked no hover
stuck. It passed before any change, because emulated touch never fires
`:hover`, so it proved nothing. The spec now walks the stylesheets and fails on
any `:hover` rule outside the precise-pointer query, which listed all twelve
before the change.

The edit script's third step depended on text its first step had already
changed, and stopped halfway. It was rerun from that step, and the diff was
checked before the tests.
