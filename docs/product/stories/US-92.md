# US-92, editing an event on the calendar is only editing

Reported on 4 October 2026, with screenshots: opening an event in a calendar
day showed its controls and, under them, the form for adding another event;
and the open event had no way to change its priority.

```
US-92  As someone fixing an event from the calendar,
       I want the open event to be the only thing I am editing,
       with every detail I set when adding it,
       so that I do not wonder which form a field belongs to.

Priority: Must
Acceptance criteria:
  AC-92.1  While an event in a calendar day is open for editing, the day's add
           form is hidden. Closing the event brings it back.
  AC-92.2  An open event, on Home or in the calendar, has a Priority select
           showing its priority. Picking another saves at once, as Course and
           Goal do.
  AC-92.3  (replaced by AC-93.2) Priority sits with Course and Goal, in one
           row of three, below Due, Time and Repeat.
```

## Decisions

**Hidden by CSS, not removed.** The day shows its add form unless one of its
rows is open (`:has(.item__edit)`). Nothing about the form changes: a title
typed before opening an event is still there after closing it.

**Saved on pick.** Like Course and Goal, and as US-70 made every edit: no Save.

**Category is not in this story.** The open row cannot change category either.
Aditya asked about priority; category would be the same one select.
