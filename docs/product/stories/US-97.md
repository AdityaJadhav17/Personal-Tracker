# US-97, hardening from the audit of 13 October

The security audit of 13 October 2026 (run 2, standard profile) confirmed no
vulnerabilities. It left three open leads and a list of hardening notes. Aditya
asked for the hardening it recommended first. The leads about older copies of
locked notes wait on his decision.

```
US-97  As the only person whose data this app holds,
       I want the edges the audit found in locked notes and backups closed,
       so that a passcode change, a second window or a stray file cannot
       quietly cost me notes or backups.

Priority: Should
Acceptance criteria:
  AC-97.1  After the passcode changes, Undo cannot bring back a locked note
           deleted before the change: it would be sealed under the old
           passcode, open with neither, and block every later change.
  AC-97.2  When a passcode is first set in one window while another window
           has already set one, the second does not replace the first. It
           says so, and nothing is locked under it.
  AC-97.3  Backup files in the folder dated after today are neither counted
           among the 30 kept nor deleted, so a file named for a future day
           cannot push the real backups out.
```

## Decisions

**The spike stays.** The audit suggested deleting `spike/ios-push`, but
v3-plan says to delete it once it has answered its questions, and it has not.
It is never deployed or run by either task.
