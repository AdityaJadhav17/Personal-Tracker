# US-48, feedback where it was missing

Phase 2 of the [UI polish plan](../../design/ui-polish-plan.md), from
find-animation-opportunities and apple-design. Built 24 September 2026.

```
US-48  As someone moving things around the calendar and the list,
       I want to see where a drag will land and see panels arrive,
       so that nothing I do happens off to the side without a trace.

Priority: Should, built
Acceptance criteria:
  AC-48.1  Given I drag an item over the calendar, the day under the pointer
           is highlighted the moment the pointer arrives, and nothing is
           highlighted after the drop, a cancel, or leaving the grid.
  AC-48.2  Given an item row or a calendar day opens, or a status message
           appears, it fades in and rises into place instead of appearing:
           4px over 150ms for rows, 200ms for the day, 2px for messages.
           Reduced motion keeps the fade and drops the rise.
```

## Decisions

**The highlight is instant.** It tracks the pointer, so any transition would
make it lag behind the thing it describes.

**Entrances use `@starting-style`,** CSS only, and animate `opacity` and
`translate`, never height, which would be layout. The distance is the `--rise`
token from US-47, so reduced motion stills it in one place.

**Status messages keep their live region.** The `role="status"` element stays
put, which is what makes screen readers announce it; the message inside is
re-inserted per message, which is what lets it enter.

## What it took

Leaving the grid was first detected with `relatedTarget` on `dragleave`. Chrome
leaves that empty on drag events, so every crossing between a cell and its own
children read as leaving, and the highlight was cleared as soon as it was set.
The grid now counts enters and leaves and clears at zero.

Moving from one cell to the next fires `dragenter` on the new cell before its
first `dragover`, which in Playwright only comes with the next movement. The
new cell now lights on `dragenter` too, so it is immediate everywhere; in real
Chrome, `dragover` alone would have lagged by up to 50ms.
