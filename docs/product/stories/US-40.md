# US-40, keeping the data safe

Step 1 of [the roadmap](../review-and-roadmap.md). Built 24 September 2026.

Everything the app knows lives in one browser's storage for one address, and
nothing prompted a backup. Two known warts from earlier stories and one
unexplained partial deploy sat in the same area, so they are fixed here too.

```
US-40  As someone whose deadlines exist in one place only,
       I want the app to guard that copy and nudge me to back it up,
       so that clearing site data is an inconvenience, not a loss.

Priority: Must, built
Acceptance criteria:
  AC-40.1  Given the app loads,
           then it asks the browser to keep its storage persistent.
  AC-40.2  Given items that have never been exported,
           then a line by Export says "Not backed up yet."
  AC-40.3  Given the last export was under a week ago, nothing is said;
           a week or more says "Last backup N days ago."
  AC-40.4  Given I export,
           then the reminder goes, stays gone after a reload, and the file
           records when it was taken.
  AC-40.5  Given the browser refuses to save a new item,
           then the form keeps what I typed.
  AC-40.6  Given a monthly item on the 31st,
           when it passes through a short month,
           then it comes back to the 31st afterwards.
  AC-40.7  Given a version 3 database or export,
           then it upgrades to version 4 with nothing lost.
  AC-40.8  Given a deploy that leaves index.html and assets/ disagreeing,
           then npm run deploy fails and says which files.
```

## Decisions

**Version 4, two fields.** `lastBackupAt` on the database and `repeatDay` on
each item. Both need to survive a reload, and the database is the one place
things survive. One hop in `migrate.ts`, as `CLAUDE.md` promises.

**`repeatDay` is set only when it matters.** It stays null until a monthly
item is finished, then carries the day the series aims for. Moving the
deadline by hand clears it, because a new date means a new aim.

**The reminder waits a week.** A line that is always on screen is one you
stop reading.

**`persist()` without a fallback.** Chrome grants it to installed apps. If it
declines, nothing changes and Export is still the backup.

**The deploy check looks both ways.** The broken deploy left an old
`index.html` pointing at old files that still existed, so checking only that
its files exist would have passed. Checking that every file in `assets/` is
used as well catches it. Tested against a copy of that exact state.

## What it took

`addItem` now reports whether the save worked, which is the whole of the
AC-40.5 fix: the form only clears on success. The test that used to retype
after a refused save no longer needs to.

The deploy check was tested once by mistake against the real deploy folder,
which put this story's code live on `localhost:4180` before it was committed.
It was fully tested at that point and the migration is additive, but the
check is exercised against scratch folders from here on.
