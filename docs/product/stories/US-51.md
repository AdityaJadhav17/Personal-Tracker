# US-51, choosing light or dark

Asked for on 24 September 2026: the app had a light mode that could only be
reached by changing Windows' own setting.

```
US-51  As someone who reads this at different times of day,
       I want a button that switches between light and dark,
       so that the app's look is mine to choose, not only the system's.

Priority: Should, built
Acceptance criteria:
  AC-51.1  Given the page is light, the sidebar offers "Dark mode"; pressing
           it switches the page, and the button then offers "Light mode".
  AC-51.2  Given I have chosen, the choice survives a reload and wins over
           the system's setting.
  AC-51.3  Given I have never chosen, the page follows the system, and nothing
           is forced.
  AC-51.4  Given either choice, every colour pair still meets WCAG 2.2 AA, and
           each scheme-dependent colour is declared once for both schemes.
```

## Decisions

**light-dark() tokens.** Each colour is now `light-dark(light, dark)` in
`styles/base.css`, chosen by the page's `color-scheme`. That follows the system
by default, and the toggle sets `data-theme` on `<html>` to force one. The
alternative was a second copy of the dark palette for the forced case: two
lists that would drift apart. The values are unchanged, and the contrast test
now reads both palettes from the one declaration.

**A script before paint.** `public/theme.js` is a classic script in `<head>`
that applies a saved choice before anything paints. A module runs after first
paint, so a dark choice would flash white on every open, which is the 11pm case
this app was designed around. It is served from this origin, so the existing
`script-src 'self'` allows it; the Playwright spec checks for no CSP errors.

**A display setting, not app data.** The choice lives under its own key,
`personal-tracker/theme`, beside the database rather than inside it: it is
about this browser, it is never exported, and it needed no schema version.

**Two states, as asked.** The button switches between light and dark. Once
pressed, the app no longer follows the system; clearing the key restores that.
A third "system" state would need a menu, not a button.

**A crossfade on switching.** apple-design asks for eased changes between light
and dark rather than a jump. Chrome's View Transitions crossfade the page with
no library; it is an opacity change, which reduced motion keeps.

**Placement.** Below the views on a laptop, apart from them because it changes
how things look, not where you are. Beside the title on a phone, so the icon
row gains nothing.
