# US-94, the security audit of 11 October

The audit of 11 October 2026 (security-audit skill, quick profile) confirmed no
vulnerabilities and left eleven hardening notes. Aditya asked for all of them.
He chose to skip one (binding locked text to its note id), and to try another
(install scripts off) in a scratch folder before adopting it.

```
US-94  As the only person whose data this app holds,
       I want the audit's hardening notes closed,
       so that each boundary holds without relying on a second one.

Priority: Should
Acceptance criteria:
  AC-94.1  The server on 4180 tells browsers never to show it inside a frame:
           X-Frame-Options DENY and frame-ancestors 'none' on every answer.
  AC-94.2  Every date read from an import is stored in one form, the ISO
           instant JavaScript writes (2026-09-15T17:00:00.000Z), whatever
           form the file used. A date the file wrote another way still
           imports.
  AC-94.3  The calendar export writes DTEND from the instant, as DTSTART
           already is, never from the stored text.
  AC-94.4  The updater counts only check runs for the commit it is deploying,
           reads up to 100 of them, and treats the run named check as CI only
           when GitHub Actions posted it.
  AC-94.5  The updater never deploys a commit older than the one deployed:
           when main has moved backwards, it logs that and stays put.
  AC-94.6  CI pins each action to a full commit ID, and Dependabot proposes
           updates to those pins weekly.
  AC-94.7  npm ci runs with install scripts off, in CI and in the updater, if
           build and tests pass that way. (Dropped, with the reason recorded
           here, if they do not.)
  AC-94.8  Merging a file adopts its passcode lock only when the file brings
           locked notes with it.
  AC-94.9  When another tab of the app saves, this tab takes up what it saved
           instead of later writing its own older copy over it.
  AC-94.10 A new or changed passcode needs at least 8 characters. A passcode
           set before this still opens its notes.
  AC-94.11 A title read from an .ics file loses invisible direction-control
           characters and keeps at most 200 characters.
```

## Decisions

**Normalise, do not narrow.** Rejecting non-ISO dates would refuse backups that
open today. Storing `new Date(value).toISOString()` keeps every file that
imports now importing, and gives every later reader one form.

**No binding of locked text to its note id.** Swapping two locked notes' text
needs write access to the browser's storage, and whoever has that already runs
script in the page. Old notes would need a second way to open. Not worth it.

**Older commits are refused, not deployed.** A force-push backwards is either a
mistake or deliberate; if deliberate, `npm run deploy` is one command.

**8 characters, not 6.** Only setting or changing a passcode checks it, so a
6-character passcode set before this still unlocks.
