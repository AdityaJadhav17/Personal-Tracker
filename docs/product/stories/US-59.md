# US-59, the opened row

The third story from the UI audit of 24 September 2026. Built the same day.

```
US-59  As someone who opens a row to change it several times a day,
       I want its fields laid out in the order I think about the item,
       so that editing reads as a form rather than a stack of boxes.

Priority: Should, built
Acceptance criteria:
  AC-59.1  Every field in the open row is named in visible text: Title, Due,
           Time, Repeat, Course, Goal, Note and Steps.
  AC-59.2  Every single-line control in it is the same height.
  AC-59.3  Due, Time and Repeat share a row, and Course and Goal the next;
           the title, note, steps and buttons run the full width. On a
           narrow screen the fields stack.
```

## Decisions

**When, then what it belongs to.** A six-column grid: Due, Time and Repeat
take a third each, Course and Goal a half each. That is the order of the
questions: when is it, and whose is it.

**Course and Goal got names and full size.** They were two small unlabelled
boxes after the stacked fields, the audit's clearest case of mixed sizes. The
visible word is `aria-hidden` and the accessible name still carries the
item's title, as the other fields already did, so twenty open rows stay
individually addressable.

**The note is an ordinary field.** It used to shrink to a one-word placeholder
while empty. With the note now shown on the closed row (US-57), the open row
can give it a plain labelled box three lines tall.

## What it took

The drop confirmation sits on the closed row, outside the grid, so its
full-width rule stayed. An unused `.item__course` rule in `CourseList.css`
went.
