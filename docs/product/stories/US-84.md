# US-84, tests that pass on any day

Asked for on 30 September 2026, the last day of a month, when five Playwright
specs failed on the laptop and passed on CI, which was already in October.

```
US-84  As the person who reads a red CI run,
       I want the tests to give the same answer whatever day they run,
       so that red means the app broke, not that the calendar moved.

Priority: Must
Acceptance criteria:
  AC-84.1  Every Playwright spec runs with the page's clock starting at one
           fixed moment, Tuesday 15 September 2026, 10:00 local, and moving
           forward from there in real time.
  AC-84.2  Dates the specs work out in Node (what to type, what to expect)
           come from that same moment, never from the machine's clock.
  AC-84.3  A spec cannot forget the clock: importing `test` from
           @playwright/test directly in e2e/ fails lint.
  AC-84.4  Every unit and component test runs with Date at that same moment.
           Tests that fake timers themselves keep it.
  AC-84.5  The whole suite passes with the machine's clock and zone
           anywhere: proven by running it in the laptop's zone and in UTC.
```

## What was found

- Playwright: 24 spec files and the shared helpers read the real clock in
  Node, and the page reads it too. On the last day of a month, "tomorrow" is
  in the next month and off the calendar grid; on 1 October a monthly item
  is 31 days and an hour from its next, because the clocks go back on
  1 November. Five specs fail today. us-21 and us-42 already pin the clock
  by hand, after the CI failure of 29 September.
- Unit tests: `App.test.tsx` renders the real app against the real clock with
  41 dates written out in September to November 2026. Run with the clock at
  10 October, two fail; at 15 September all 879 pass. Left alone, CI goes red
  around 4 October with no change to the app.

## Decisions

**One moment for everything: 15 September 2026, 10:00 local.** Mid-month, a
weekday, mid-morning, seven weeks from a clock change. The unit tests already
use it in `dates.test.ts`, and every written-out date in the tests was
written against a September "today".

**Time moves from there.** Frozen time would give every note and item the
same timestamp, and the order of notes is by edit time. The page clock is
installed at the moment and resumed, so it ticks normally.

**One place.** `e2e/clock.ts` exports `TODAY` and a `test` whose fixture sets
the page clock before each test; specs import `test` and `expect` from it.
`helpers.ts` builds its dates from `TODAY`. The hand pins in us-21 and us-42
go, since every spec has one now. The unit tests set Date in
`src/test-setup.ts`, faking Date only, so timers, user-event and Web Crypto
are untouched.

**Lint keeps it.** `no-restricted-imports` on e2e/ names the one file allowed
to import `test` from Playwright.

**Not in this story.** The app itself: nothing here changes what it does.
