# US-49, type and contrast

Phase 3 of the [UI polish plan](../../design/ui-polish-plan.md), from
apple-design. Built 24 September 2026.

```
US-49  As someone reading this at 11pm on a laptop,
       I want text that follows my size setting and edges I can see,
       so that the app adjusts to my eyes rather than the other way round.

Priority: Should, built
Acceptance criteria:
  AC-49.1  No stylesheet sets a font size in pixels, so text follows the
           browser's font size setting as well as its zoom. At the default
           size nothing moves.
  AC-49.2  When the system asks for more contrast, borders reach 3:1 against
           the page and a card, and muted text is stronger than usual, in both
           schemes.
  AC-49.3  Every view passes the WCAG 2.2 AA scan with more contrast, in both
           schemes.
  AC-49.4  Large text is tracked tighter; nothing below body size is.
```

## Decisions

**Pixels to rem, one for one.** 64 declarations, each divided by 16. Every
view was screenshotted in both schemes before and after with a pinned clock,
and all twelve images came out byte for byte identical.

**Two tokens change for more contrast, nothing else.** apple-design asks for
"near-solid backgrounds with a defined, contrasting border". The surfaces are
already solid, so only `--border` (to `#64748b` in light, `#7c8aa5` in dark)
and `--text-muted` (to `#334155` and `#cbd5e1`) move. It is a block in
`base.css` that redefines tokens, so the toggle's `data-theme` still picks
the scheme and the contrast test reads it.

**Tracking by size.** The stat numbers tighten by `-0.02em` and the 18px
titles (month, Reflections, Trends) by `-0.01em`. The small uppercase labels
keep their positive spacing, which is what the skill asks for at that size.
The sidebar title keeps its existing `-0.01em`: it is body size, where the
skill says near zero.

**Spacing stays in pixels.** apple-design would also have padding and gaps in
rem so layout grows with text. That touches every rule in the app; left until
a larger font setting shows a layout that breaks.

## What it took

The contrast test read every token in `base.css`, so the new block would have
silently replaced the normal palette in every existing test. It now reads the
normal tokens and the more-contrast block separately and lays one over the
other.

`font-size: 0` reads back from the CSSOM as `0px`, so the pixel check skips
zero, which needs no unit to scale.
